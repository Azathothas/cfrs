Each binary is static (musl). It needs no C library on the host. `cfrs.1`
is the manual page.

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.4 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

`cfrs update` from 0.3.0-beta.3 does these checks itself.

## Changes for a tester

* `tunnel --url`: a WebSocket to the origin gets the upgrade on the QUIC
  leg (#56).
* `share`: an upload is staged and is kept all or nothing; a session has a
  total limit (4 GiB); a chunk that takes more than 60 s gives 408; a
  download name that is not ASCII is sent by RFC 5987 (#58, #59, #60).
* `cfrs pod`:
  * the program does not get the host proxy variables
    (`--keep-proxy-env` keeps them), and the `netns` backend gets a
    resolver that it can reach (#61);
  * a bad upstream or `--rule` exits 64 and does not run the program
    (#62);
  * with `seccomp`, an inbound listener wakes `poll`, `select` and
    `epoll`, and `accept` does not stop the program (#69).
* `cfrs net`:
  * `socksify --socket PATH` gives the SOCKS socket (#63);
  * the shim gives a free port for a bind to port 0, keeps the peer of
    `accept`, and caches a build (#64);
  * a stack reaches its own forward through a switch (#65);
  * `net demo` closes both sockets and checks the teardown (#53).
* CLI:
  * bad input gives a usage error (exit 64), not a panic;
  * a closed pipe stops the commands that only print;
  * a failure report has the error one time (#57, #55).
* `CFRS_EDGE` and `CFRS_UDP` are checked the same way by each command;
  a bad `RUST_LOG` is named (#66).
* `--ha-connections` is for redundancy, not for throughput (#54).
* `warp`: `status --json` hides the license key; `warp probe` takes a
  host name (#68, #67).
* The WARP leg: the h2 budget for small DATA frames holds a full stream
  window of the smallest packets. The budget before held about 42000
  frames, and a slow receive task could still close the connection with
  ENHANCE_YOUR_CALM (#32).
* The QUIC legs: the edge can open 256 streams at the same time (one for
  each visitor request; quick tunnels allow 200). The limit before was
  100. The WARP QUIC leg starts at a UDP payload of 1232 bytes.
* The HTTP/2 leg: a GOAWAY of the edge starts a replacement connection at
  once, also while a stream (a WebSocket) is open. Before, the replacement
  started only when the last open stream ended. The open streams of the
  old connection go on to their end.
* The QUIC leg: an RPC stream of the edge is reset at once. Before, it was
  logged as a failed visitor stream.
* `cfrs update` downloads a binary of up to 128 MiB. The limit before was
  16 MiB, near the size of the binaries.

## What to report

Open an issue with:

* the output of `cfrs --version`, `cfrs status` and `cfrs doctor --json`;
* the command, and its output with `RUST_LOG=cfrs=debug`;
* the network limits of the host (proxy, UDP, ports, DNS, TLS interception).

`CFRS_ERROR_PROGRAM=/path/to/program` gives each failure as one JSON
document to that program, with the credentials masked.

## Limits of this prerelease

* Linux only.
* A proxy that terminates TLS cannot carry the edge connection or the WARP
  MASQUE connection.
* The `netns` backend of `cfrs pod` carries TCP and DNS, not other UDP.
