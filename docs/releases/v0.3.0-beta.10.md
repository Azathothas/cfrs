## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.10 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.3.0-beta.10   # rebuild and compare (x86_64, aarch64)
```

`cfrs update` from 0.3.0-beta.8 does the first three checks itself.

## Breaking

Changes that a command written for beta.9 can need:

* Exit codes (#210, #173, #172):
  * A refused provision of a quick tunnel (HTTP 429) exits 75 (before:
    69). The error report has `status`, `code`, `retry_after_s` and
    `retryable`.
  * `--detach`: no ready in `--ready-timeout` exits 124 (before: 75).
  * A bad tunnel token or credentials file exits 78 (before: 1);
    `--token` with `--credentials-file` on one command line exits 64.
  * `--check` exits 78 when each failed check is a check of the
    configuration (`CFRS_EDGE`, a credentials file, the roots).
  * A `--ca-file` that cannot be used exits 78 for each command, also
    `status` and `doctor` (before: `status` exited 0).
  * `share --mode download` with no `--file`, `--mode proxy` with no
    `--port` or `--unix`, a protocol that the transport cannot carry,
    `autostart add` with a bad name or command, `warp license` with a key
    that the API refuses, `share --max-request 0`, `warp license ''`: 64.
  * `net proxy --switch` that does not answer: 69; a bad value: 64.
  * `agent up`: an expose that failed exits 69.
* `--detach`: a planned end (`--stop-after`, `--idle-secs`, `--run-for`)
  is not restarted (#195).
* `cfrs connect` (#191, #202, #207):
  * It dials through `--proxy`, `--resolve`, the system resolver and DoH,
    with the roots of `--ca-file` (before: the system resolver and the
    webpki roots).
  * It opens one WebSocket to the remote at start and exits 69 when the
    remote does not answer. `--no-check` starts without the check.
  * A unix socket of `-L` that another process serves is refused (exit
    69); `--replace` takes it. A file that is not a socket exits 64. At the
    end, connect removes the socket files that it made.
* `--config` (#171, #170, #172): `protocol:` and `ha-connections:` of the
  file are used (before: the defaults of the flags replaced them). A flag
  wins over the file. A key of a rule or of `originRequest` that cloudflared
  does not know is an error (exit 78); before, `hostnam:` made a catch-all
  rule. The top-level `originRequest` is the default of each rule.
* `cfrs update --version` of the installed version does nothing and exits
  0; `--force` installs it again (#197).
* `warp nc` sends no FIN at the end of stdin; it ends when the far end
  closes, or `--idle` seconds (default 5) after the last data. `-N` gives
  the old behaviour. An error of the far end exits 69 (#188).
* `share`: a locked request other than GET or HEAD gets 403 (before: 200
  with the PIN page). A wrong PIN gets 403 (#194).
* `tunnel --tcp`: an HTTP request gets 501, and the public URL is not
  verified (#199).
* `--name` with no `--detach` registers the process (before: exit 64).
  `--replace` needs `--detach` (except for `connect`); `--no-restart`
  needs `--detach` or `--name` (#209).
* `net proxy`: `--drop`, `--duplicate`, `--reorder` and `--seed` need
  `--switch` and a probability from 0.0 to 1.0 (#196).
* `cfrs OPTION pod` with `--proxy`, `--no-proxy`, `--resolve` or
  `--ca-file` exits 64: give the proxy of the pod with `-x` (#189).
* The pod (netns backend): a connect to a dead upstream fails with
  `ECONNREFUSED` (before: it succeeded, then the first read failed) (#190).

## Fixed

* `cfrs -v pod -- PROG` (a global option before `pod`) panicked (#189).
* The detach supervisor restarted a planned end with a new URL (#195), and
  counted a 429 as a quick failure, which swapped in `cfrs.prev` (#182).
* PID 1 of a container ignored SIGTERM before the ready line (#208).
* `warp export` wrote the WireGuard private key to a terminal and to a
  0644 file (#177).
* `install.sh`: busybox wget checks no TLS certificate (it is last, with a
  warning); a binary that does not run replaced the old one; a cut
  download looked like a SHA256 mismatch (#174, #175, #169).
* A misspelt key of a rule made a catch-all rule (#170).
* `--run-for` did not end the verify (#179).
* A restarted detached child wrote each log line two times (#182).
* `cfrs connect` ignored `--proxy` and DoH (#191).
* The shim answered `0.0.0.0:0` for the local address of a connected
  client (#193).

## Changes for a tester

### Tunnels

* `--auth-user` and `--auth-password-file`: HTTP Basic in front of a
  tunnel; `cfrs connect --auth-user` for `--forward` (#205).
* `--forward`: the ready event, the ready document and `cfrs ps` give the
  `wss://` endpoint (#203).
* `share --mode proxy --unix PATH` (#204).
* `cfrs connect --detach`, `--name`, and the time of each step at `-v`
  (#207, #206).
* `--protocol quic` with a proxy keeps the leg, with a warning (#182).

### WARP

* `--session-max-age SECS`: a new session (and egress address) at that age
  (#185). The log names the cause of each close of a session (#178).
* `warp exit` gives the IPv6 egress address (#184).
* A 429 of the registration names a saved identity (#187).
* `warp proxy` refuses a SOCKS4 client at once (#178).

### Install and update

* `install.sh` and `cfrs update`: a pinned tag needs no GitHub API; the
  newest release falls back to `releases.atom` (#166). The documented form
  is `s=$(curl -fsSL URL) && sh -c "$s"`: a pipe to `sh` exits 0 when curl
  fails (#165). `notebooks/install.ipynb` for a host with no lasting disk
  (#192).

### Diagnostics

* `cfrs doctor`: a local refusal is an answer; one line for a failed
  lookup; the advice of a Digest 407 (#180).
* `--log-format json`: the last error line is JSON too (#181).
* `cfrs wait NAME` of a name that never existed says so (#182).

## What to report

* `live.yml` prints the median time of 20 small requests over the URL and
  over `cfrs connect` (#206): a gap on a proxy-only host.
* `warp exit --json` on a host with IPv6: does `ipv6` come from the trace,
  or from `whoami.cloudflare` (#184)?

## Limits

* `--session-max-age` does not apply to `warp tun`.
* The pod carries no ICMP; only `warp run --backend netns-raw` does.
