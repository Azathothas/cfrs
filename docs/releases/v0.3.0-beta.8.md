## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.8 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

`cfrs update` from 0.3.0-beta.7 does these checks itself.

## Breaking

Changes that a command written for beta.7 can need:

* The SOCKS5 server of `warp proxy` answers 0xff (no acceptable method) to a
  client that offers no method the server takes. Before, a client that
  offered only user and password (0x02) to a proxy with no credentials got
  0x00. A client that offers 0x00 is served as before (#146).
* `warp proxy` refuses a loopback, a link-local or an unspecified address,
  and `localhost`, with SOCKS5 reply 0x02 or HTTP 403. Before, the
  connection went into the tunnel and failed after up to 15 s. A rule
  (`-r cidr:127.0.0.0/8=direct`) changes this (#132).
* pod-netns, library: `RuleMatch::Cidr` holds a list of IPv4 or IPv6
  prefixes (`Arc<[Net]>`), not one IPv4 address and a length. Use
  `RuleMatch::parse("cidr:10.0.0.0/8")` (#142).
* The stack of WARP sends no new packet while its outbound queue is full,
  in place of a drop (#134).

## Changes for a tester

### New commands and flags of `cfrs warp`

* `warp exit [--json]`: the colo, the country and the address of the exit
  of the session. `warp probe` prints one `exit` line (#147).
* `warp forward -L LISTEN=HOST:PORT`: as `ssh -L`, through WARP; HOST is
  resolved inside the tunnel (#143).
* `warp scan [--candidate IP[:PORT]]`: the TCP and TLS time of each front
  door, with the pinned key (#139).
* `warp export [--format wg-quick|json] [--delete]`: a WireGuard device with
  its own key, for other clients (#148).
* `warp proxy -r KIND:VALUE=ACTION`, `--rules-file`, `--rule-default`,
  `--check`: tunnel, direct or reject for each destination; the file is
  read again when it changes (#132, #136).
* `warp proxy --listen-identity LISTEN=PATH`: one device for each listener
  (#150).
* `warp proxy --proxy-user USER --proxy-password-file FILE` (also on
  `warp up`): SOCKS5 user and password, HTTP Basic (#146).
* `warp --resolver SPEC` (`CFRS_WARP_RESOLVERS`): the DNS resolvers inside
  the tunnel, UDP or DNS over TLS (#145, #144).
* `warp --device-name`, `--device-model`, `--device-locale`: what a new
  device declares (#141).
* `warp --fragment-client-hello [record|sni]`, `--fragment-size`: the TLS
  ClientHello of the MASQUE connection in more than one record (#135).
* `warp up --env-d`: the proxy variables in
  `~/.config/environment.d/90-cfrs-warp.conf` for the next login (#138).

### Paths and counters

* The front door that carried data is kept for 7 days in
  `warp-door.json`; a door whose session carried no packet goes last (#133).
* `cfrs_decisions_total{decision,outcome}` in the metrics: DNS steps,
  egress, legs, MASQUE paths, proxy requests and rules (#137).
* The health line of `warp proxy` has the decisions, `tx_dropped` and
  `tx_held` (#134, #137).
* pod-netns: `-r cidr:` takes IPv6 prefixes and `cidr:@FILE` (#142).

### An IPv6-only host (#163)

* DNS over HTTPS by the IPv6 addresses of 1.1.1.1 and 8.8.8.8, in the order
  of the routes of the host.
* `warp tun --default-route` routes the front door in use (IPv4 or IPv6),
  and skips a relay address that has no route.
* `cfrs doctor` measures the IPv6 front door.
* `scripts/v6only/`: an IPv6-only network namespace on a runner, with its
  live step.

### Recipes

* Tor, Psiphon, and a nested session (a second device through the first):
  `docs/target-environment.md` (#156, #158, #159).
