is the manual page.

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.6 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

`cfrs update` from 0.3.0-beta.5 does these checks itself.

## Changes for a tester


The fixes of the reports on beta.5 (#97 to #108).

### WARP

* `warp proxy` binds each `--listen` on its own: a listener that the host
  refuses is reported, and the proxy starts with the others (`--strict`
  exits 69). `warp up` starts with the unix socket alone on a host that
  refuses TCP binds; `warp env` and `warp exec` follow (#97).
* `warp tun --default-route` works on a host with no default route when the
  MASQUE connection goes through a proxy on loopback or on a connected
  subnet; an address with no route is refused with its name (#105).
* The keepalive of a MASQUE session works: a PING only when the session is
  idle, the pong is awaited, and a session with no pong and no data is
  replaced. The wait for HTTP/2 send capacity has a limit of 30 s (#104).
* `warp up --tun`: the error names its command, the cause and the recovery
  (`sudo`, proxy mode, `warp run`) (#106).
* The TCP window of the userspace stack (`warp proxy`, `warp up`) is one
  segment, as in beta.5: larger windows stall on the WARP path, and the
  cause is open (#100). `CFRS_WARP_TCP_BURST=N` sets it for a
  measurement. `warp run --backend netns-raw` uses the kernel TCP and has
  no such limit.

### Pods

* An errno of the seccomp supervisor is a failure of the system call.
  Before, each one was a positive return value: for example,
  `io_uring_setup` returned 1, and a refused connect returned 111 (#98).
* `getsockname` and `getpeername` write through `process_vm_writev` when
  `/proc/<pid>/mem` is not writable; with neither, they fail with
  `EOPNOTSUPP`, not with an `AF_UNIX` address. `pod doctor` shows the row
  `write program memory` (#98).
* IPv6 by name under `seccomp`: AAAA gets an address of
  `fd63:6672:7300::/96`, and a connect to it sends the name to the proxy
  (#99).
* `-x http://unix:/path` is an HTTP CONNECT proxy on a unix socket (#102).

### Tunnels and the CLI

* A stop signal after the ready line, also during the verify of the public
  URL, is a clean stop (exit 0) (#101).
* `share --max-request`: a larger upload is read and dropped before the
  413, so that the visitor gets the 413 and not a 502 or a 520 of the edge.
  After any early answer, the rest of a request body is read for a time.
* An unavailable path exits 69 in each command: `warp tun`, `warp proxy`,
  `warp up` (it passes the code of its child), `agent up` when WARP was
  needed (#102, #97).
* `cfrs logs`: each start writes a separator line with its pid, and the log
  has the lines from the start of the instance, with no colour codes
  (#103).
* `doctor --agent`: the UDP line says that it is the direct UDP of the host,
  and names the commands that give UDP through WARP (#107).

## What to report

Open an issue with:

* the output of `cfrs --version`, `cfrs status` and `cfrs doctor --agent`;
* the command, and its output with `RUST_LOG=cfrs=debug`;
* the network limits of the host (proxy, UDP, ports, DNS, TLS interception).

`CFRS_ERROR_PROGRAM=/path/to/program` gives each failure as one JSON
document to that program, with the credentials masked.

## Limits of this prerelease

* Linux only.
* A proxy that terminates TLS cannot carry the edge connection or the WARP
  MASQUE connection.
* The `netns` backend of `cfrs pod` carries TCP and DNS, not other UDP; use
  `--backend seccomp` or `netns-raw` for other UDP.
* TCP through `warp proxy` and `warp up` has a window of one segment: about
  0.5 MB/s at an RTT of 40 ms (#100).
* The relay limits each session to 64 MiB and 12 h.
