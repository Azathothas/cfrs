Each binary is static (musl). It needs no C library on the host. `cfrs.1`
is the manual page.

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.3 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

`cfrs update` from 0.3.0-beta.2 does these checks itself.

## Changes for a tester

* `cfrs doctor`: the path from the host to the edge. It gives the proxy,
  TCP and TLS to the APIs, to the edge (by name and by address) and to the
  MASQUE front door, the TLS issuer, UDP 7844, and the legs that can work
  (#11).
* `--check` on `tunnel`, `serve`, `share` and `demo`: check the plan and
  stop, with no Cloudflare call (#45).
* `cfrs autostart`: start a command at boot with a systemd user unit or a
  crontab `@reboot` line, no root, no secret in the unit (#23).
  `CFRS_PROXY` gives `--proxy`.
* `CFRS_UDP=off|on|probe`: a QUIC probe on UDP 7844; a refused probe skips
  the QUIC leg. `cfrs net doctor` tests `listen` after `bind`, and UDP
  egress (#12).
* The WARP leg: backpressure on the MASQUE send, and a new WARP session
  after a loss (#32).
* Registration sends the features of cloudflared 2026.10.7 (#14).
* Fixes of tester reports: the shim gives a peer address to `accept`, so a
  Perl server serves each connection; `net proxy` answers 502 or 504 with
  a body, and a `--forward` to another address works; `net tailscale`
  checks its socket at start (#41). `serve --spa` needs `index.html`, a
  FIFO or a long name gives 404 (#37). `share` resumes downloads and shows
  upload progress (#46). Log controls `-q`, `-v`, `--color`,
  `--log-format json` (#44).
* `fuzz/`: libFuzzer targets for each parser of network bytes; one fault
  in the Cap'n Proto reader is fixed (#5).

## What to report

Open an issue with:

* the output of `cfrs --version`, `cfrs status` and `cfrs doctor --json`;
* the command, and its output with `RUST_LOG=cfrs=debug`;
* the network limits of the host (proxy, UDP, ports, DNS, TLS interception).

`CFRS_ERROR_PROGRAM=/path/to/program` gives each failure as one JSON
document to that program, with the credentials masked.

## Limits of this prerelease

* Linux only.
* A proxy that terminates TLS cannot carry the edge connection or the WARP
  MASQUE connection.
* The `netns` backend of `cfrs pod` carries TCP and DNS, not other UDP.
