## Breaking

A command or a script written for beta.11 must change for each item
below.

Output and exit codes:

* `cfrs doctor` says `fail` where it said `refused`, in the text and in
  `--json`. Each JSON object has the key `status`; the old key `verdict`
  keeps the same value for one release. `cfrs net doctor` says `ok`,
  `fail` and `unknown` in place of `OK`, `FAIL` and `?`.
* `--detach` writes one JSON document on stdout. The human lines are on
  stderr.
* `cfrs status`: `proxy.kind` is the kind of the dial (`http`, `socks5`,
  `socks5h`, with `+unix` or `+exec`, or `direct`). It was `http` for
  each proxy.
* `cfrs wait --timeout` exits 124 at its time limit.
* `cfrs warp env` with no proxy variables exits 69 (was 0) and prints
  nothing on stdout.
* `relay connect` and `relay stop` with no pair exit 69 (was 64), and
  with a bad pair file 78 (was 64).
* `share --file` with a missing file exits 78 (was 1). `share --port 0`
  and a directory as `--identity` exit 64 (were 1 and 69).
* `warp scan --timeout-ms` outside 100 to 60000 exits 64 (was clamped).
  A bad `CFRS_RESOLVE` exits 78 for each command (was a warning).
* A missing program on `warp run --backend netns-raw` exits 3 (was 127).

Behaviour:

* A bare `cfrs share` exits 64. Give `--mode upload` or `--dir`.
* `share` uploads have mode 0600.
* The PIN cookie has `Secure`: a visit over plain http cannot unlock.
* `path:` of an ingress rule is a regular expression with no anchor, as
  in cloudflared. `path: /api` also matches `/x/api` and `/apix`, and
  `.` matches each character. Write `^/api/` for a prefix and `\.` for a
  dot. An invalid expression is a config error (exit 78).
* `tunnel --check` fails a config with no ingress rule.
* With `--leg-failover serial`, the next leg starts after at most 130 s
  (quic) or 280 s (http2), not after 8 s.
* Each unix socket that cfrs binds has one rule: a live socket is an
  error (69), a file that is not a socket is an error (64), a stale
  socket is removed (`net switch`, `net proxy`, `relay connect`,
  `warp proxy`).
* Root with the `HOME` of another user writes no file there.
  `CFRS_FOREIGN_HOME=allow` writes anyway.
* `net ts-shims --out` refuses a directory of another user, or one that
  other users can write.
* `cfrs net`: a process of another user (also root) cannot use the
  switch unix socket, the control socket of the shim, an imported name or
  a shim listener.
* `cfrs net switch --listen tcp://...` needs a token: set
  `CFRS_SWITCH_TOKEN`, or give `--switch-token-file`, to the switch and
  to each `net proxy --switch tcp://...`. With no token, the switch exits
  64.
* `cfrs pod`: the default inbound directory is
  `$XDG_RUNTIME_DIR/pod-netns-inbound`, else
  `$TMPDIR/pod-netns-inbound-<uid>`; it was `/tmp/pod-netns-inbound`. An
  `--inbound-dir` of another user, or one that the group or others can
  write, is refused.

Library (`cfrs` crate):

* `StaticServer::respond` gives a `StaticResponse` with a reader body
  (`StaticBody`), not a `BufferedResponse`. A large file gets 200, not
  413. `StaticDir` refuses dotfiles. A `ResponseWriter` can get more than
  one `body()` call for one response.
* `IngressRule::path` is `Option<PathPattern>`, not `Option<String>`.
* `vnet::switch::serve` and `attach` take a token argument.
* `cfrs::feature::MetricsEndpoint`, `metrics_response`, `METRICS_PATH`
  and `cfrs::util::metrics` are removed. The library relay puts its
  default origin socket in a private directory of the user.

## Fixed

This release has the fixes of the issues #212 to #258 and #279 to #309
(the QA findings), and the podssh study. Each commit names its issue.
The main groups:

* Proxy and fetch parsers: request heads to the origin are checked;
  hop-by-hop headers stay on their hop; limits for header lines, interim
  answers, chunk sizes and trailers; a URL fragment is not part of the
  host; a built-in body of no known size is streamed.
* Edge HTTP/2: limits for the handshake, a failed attempt and the
  configuration push. WebSocket: 502 before the dial, IPv6 relay hosts.
* Egress: an unresolvable proxy host is an error, not a crash;
  `socks5://` uses the resolver chain; Digest among other challenges.
* Share and the PIN gate: no modulo bias in the PIN, a slot before each
  compare, no host detail in errors, a depth limit for YAML, each
  multipart field counts toward `--max-request`.
* Update and install: the tag is checked before it goes into a URL; the
  new file is checked after its trial run; `--force` with no `--version`
  installs again; `install.sh` hides the token.
* Instances: a name is checked before each path; a held lock is never
  removed; the record of `--name` has no secret; `status`, `bug-report`
  and `wait` write nothing; `autostart --from` keeps the secrets.
* `cfrs pod` (seccomp backend): the doctor sets `no_new_privs` in its
  probe; `getsockname` and `getpeername` keep to the buffer of the
  caller; `SO_ERROR` gives the error of a failed connect; datagram
  lengths are checked before a read; `recvfrom` and `recvmsg` on an
  unconnected UDP socket give the real source address; a SOCKS5 user,
  password or name over 255 bytes is refused.
* `cfrs net`: a port 0 listener prints the port that it bound; the
  switch drops a frame with a spoofed source address.
* The tests skip, not fail, on a host that refuses `bind(AF_INET)` or has
  no loopback; a CI job runs them with `bind(AF_INET)` refused.

## Changes for a tester

* Update:

  ```sh
  cfrs update
  ```

* `cfrs serve --local ADDR` serves the files on a local listener (TCP
  `HOST:PORT`, or `unix:PATH`) and makes no tunnel:

  ```sh
  cfrs serve --dir ./site --local 127.0.0.1:8080
  ```

* A config of cloudflared with `token:`, `url:` or `hello-world:` works.
  A `path:` of cloudflared works as a regular expression.
* `cfrs doctor` has a last line with the step to take. `cfrs --help`
  lists the commands by purpose; each command has examples in its
  `--help` and in its man page.
* Each JSON document has `schema` and `version`.

## What to report

* `cfrs pod --backend seccomp` with a UDP program (DNS, QUIC, STUN): is
  the source address of each answer right?
* A config file copied from cloudflared that does not do the same in
  cfrs.
* `live.yml` prints the median time of 20 small requests over the URL and
  over `cfrs connect` (#206).

## Limits

* `cfrs pod --backend seccomp`: `recvmmsg` gets the `AF_UNIX` address of
  the socketpair as the source.
* `cfrs net`: a datagram socket of the shim has no same-user check.
* `path:` does not decode `%XX` before the match (cloudflared does).
* The token of a TCP switch goes over the connection as plain text: use
  a tunnel on a network that others can see.
