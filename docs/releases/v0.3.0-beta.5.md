is the manual page.

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.5 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

`cfrs update` from 0.3.0-beta.4 does these checks itself.

## Changes for a tester


This prerelease is for a host with basic networking only: start cfrs one
time, and dev work goes on.

### One command for a sandbox

* `cfrs doctor --agent` tests what dev work can do on this host (direct,
  the proxy, WARP, the relay) and prints the commands to run (#82).
* `cfrs agent up`, `down` and `status`: test, start WARP when it is
  necessary, and print what works now (#87).

### Launch one time, and forget

* `--detach` on `tunnel`, `serve`, `share`, `demo`, `warp proxy`,
  `warp tun`, `net proxy`, `net switch` and `relay node`: cfrs prints one
  JSON document when the command is ready and exits 0 (#70).
* `cfrs ps`, `stop`, `logs` and `wait` manage the instances (#71, #72).
* A supervisor starts a detached instance again with a backoff, but not
  after exit 64 or 78. A quick tunnel gets a new URL; `cfrs ps` shows it
  (#73, #74).
* `cfrs update` keeps the binary before as `cfrs.prev`;
  `cfrs update --rollback` puts it back.

### WARP

* `warp up`, `down`, `env`, `exec` and `shell`: one WARP proxy for the
  host; later shells join it with `warp env`, `warp exec` or the
  `--persist` shell block (#78, #90).
* `warp nc HOST PORT` and `warp ssh-config`: SSH and git over SSH with
  port 22 closed (#85).
* `warp tun --default-route` and `warp up --tun` (root): all traffic of
  the host goes through WARP; `stop` puts back each route and the
  resolver (#77).
* `warp run --backend netns-raw`: the TUN of a user namespace goes to WARP
  as raw IP packets: TCP, UDP, ICMP and IPv6 with no root (#79).
* IPv6 on each WARP path (#81).
* A lost MASQUE session is opened again (#75). When the direct path to
  MASQUE fails, MASQUE goes through the WebSocket relay (#76).
* Throughput: the MASQUE sender waits for HTTP/2 capacity and drops no
  ACK; one TCP download through `warp proxy` measured 1.1 to 5.4 MB/s
  in CI runs (#93).
* A proxy that gives a CA bundle of its own roots only: `warp up` merges
  it with the system bundle (#86).
* `warp probe` exits 69 when a target fails; `warp status` shows WARP+ as
  yes or no (#95).

### The edge and the relay

* `--transport relay`: the HTTP/2 leg goes in a WebSocket to a relay on
  TCP 443, for a host whose proxy does not carry port 7844.
* `cfrs relay pair`, `node`, `connect` and `stop`: inbound access (SSH, a
  debugger, a database client) to a host with outbound HTTPS only (#88).
* The ready event and the text `edge` line name the leg (#95).
* `verify`: the retries log at INFO and WARN; the `verified` event has a
  `dns` field: the resolver step that resolves the new name (#94).

### Proxies and pods

* Digest authentication to a proxy; with no proxy variable, the proxy of
  the tool configs (#83).
* `cfrs pod`: loopback goes direct under `seccomp`; `direct` rules and
  suffix rules; `--prefer-udp` (#80). With a proxy on a unix socket, UDP
  goes on the control connection (SOCKS5 command `0x83`), with no kernel
  UDP socket (#84).
* `cfrs pod --help` has the layout of the other commands; a pod with no
  proxy exits 64 (#95).

### Fixes

* SIGHUP and SIGTERM stop each server command cleanly, also with
  `--run-for`; a run under `nohup` keeps SIGHUP ignored (#91).
* `share --max-request` (default 100 MB): a larger upload gets 413 before
  cfrs reads the body. Uploads of 64 MiB pass on both legs in CI (#92).
* `--proxy` and `CFRS_PROXY` with no scheme exit 64; `serve --dir` on a
  file exits 64; `unix:///path` is `/path`; `cfrs man` takes more than one
  section; `cfrs qr` limits and checks its text; the same dial error of
  many addresses is one entry (#95).
* The LD_PRELOAD shim reads the peer name of `accept` with its length.

## What to report

Open an issue with:

* the output of `cfrs --version`, `cfrs status` and `cfrs doctor --agent`;
* the command, and its output with `RUST_LOG=cfrs=debug`;
* the network limits of the host (proxy, UDP, ports, DNS, TLS interception).

`CFRS_ERROR_PROGRAM=/path/to/program` gives each failure as one JSON
document to that program, with the credentials masked.

## Limits of this prerelease

* Linux only.
* A proxy that terminates TLS cannot carry the edge connection or the WARP
  MASQUE connection.
* The `netns` backend of `cfrs pod` carries TCP and DNS, not other UDP; use
  `--backend seccomp` or `netns-raw` for other UDP.
* The relay limits each session to 64 MiB and 12 h.
