The second prerelease of `cfrs`, for tests.

## Binaries

| File | System |
| --- | --- |
| `cfrs-x86_64-unknown-linux-musl`, `pod-netns-x86_64-unknown-linux-musl` | Linux x86-64 |
| `cfrs-aarch64-unknown-linux-musl`, `pod-netns-aarch64-unknown-linux-musl` | Linux ARM64 |
| `cfrs-armv7-unknown-linux-musleabihf`, `pod-netns-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |

| `cfrs-i686-unknown-linux-musl`, `pod-netns-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `cfrs-riscv64gc-unknown-linux-musl`, `pod-netns-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `cfrs-loongarch64-unknown-linux-musl`, `pod-netns-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `cfrs-powerpc64le-unknown-linux-musl`, `pod-netns-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host. `cfrs.1`
is the manual page.

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
```

From this release, `cfrs update` does these checks itself.

## Changes for a tester

* `cfrs update`: install a release after a check of its signature and its
  SHA-256.
* Proxies: `--proxy`, `--no-proxy`, `socks5://`, `socks5h://` and
  `NO_PROXY`, for each connection. With a proxy, `--protocol auto` does not
  try UDP. A 407 answer names the schemes that the proxy asks for.
* DNS: with no system resolver, cfrs uses DNS over HTTPS by IP address
  (Cloudflare, then Google). `--resolve HOST=IP` pins a name.
* TLS: `--ca-file` and `SSL_CERT_FILE` (the root of a proxy that inspects
  TLS), the system bundle, and the clock of the host in a certificate error.
* The HTTP/2 edge leg sends PING, follows GOAWAY with no lost request, and
  obeys the retry flags of the edge. A leg retries network errors with no
  limit.
* Files: the WARP identity is in a private state directory, never in the
  current directory. `CFRS_STATE_DIR=none` keeps no file.
* `cfrs man`, `cfrs status`, `--json` for the tunnel commands and `cfrs
  ports`, sysexits exit codes, and `CFRS_ERROR_PROGRAM` for failure reports.
* `SECURITY.md`: what Cloudflare sees, what listens, where secrets are.

## What to report

Open an issue with:

* the output of `cfrs --version` and `cfrs status`;
* the command, and its output with `RUST_LOG=cfrs=debug`;
* the network limits of the host (proxy, UDP, ports, DNS, TLS interception).

`CFRS_ERROR_PROGRAM=/path/to/program` gives each failure as one JSON
document to that program, with the credentials masked.

## Limits of this prerelease

* Linux only.
* A proxy that terminates TLS cannot carry the edge connection or the WARP
  MASQUE connection.
* The `netns` backend of `cfrs pod` carries TCP and DNS, not other UDP.
