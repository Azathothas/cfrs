## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify cfrs-x86_64-unknown-linux-musl --repo Azathothas/cfrs
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/v0.3.0-beta.9 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.3.0-beta.9   # rebuild and compare (x86_64, aarch64)
```

`cfrs update` from 0.3.0-beta.8 does the first three checks itself.

## Breaking

Changes that a command written for beta.8 can need:

* The TCP window of the userspace stack of WARP has no limit by default
  (before: 1 segment). `CFRS_WARP_TCP_BURST=1` gives the old window (#100).
* smoltcp is 0.12 (before: 0.11), in cfrs and in pod-netns.
* The vnet stack takes an MTU from 576 (before: at least 1280).

## Fixed

* An upload through the userspace stack of WARP (warp proxy, warp run, warp
  nc) of more than the send buffer sent some bytes twice: the TLS server
  answered `bad record mac`. Each byte now goes once. beta.8 and before have
  the fault (f55dd65).

## Changes for a tester

### Transports of the tunnel

* `warp --masque-transport h3`: MASQUE over HTTP/3 on UDP 443. Each IP packet
  is an HTTP datagram (#157).
* `warp --transport wireguard`: the tunnel on WireGuard (UDP 2408), with the
  device of `warp export` (#152).
* `warp --carry wg`: a second WireGuard device inside the tunnel; a
  destination sees its exit. With `--transport wireguard`, both hops are
  WireGuard (#154, #155).
* `warp --cc none|reno|cubic`: the congestion controller of the TCP
  connections of the stack (#134).

### Proxy

* `warp proxy --l4`: one HTTP/3 CONNECT for each TCP client, with no IP
  stack (#140). The door of WARP does not take it yet: a report only.

### Release

* `scripts/rebuild.sh TAG`: rebuild a release and compare it with
  SHA256SUMS. `release-proofs.yml` runs it for x86_64 and aarch64; the
  binaries of beta.8 were the same (#162).
